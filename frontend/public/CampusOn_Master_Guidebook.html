1. Executive Overview & 4-State Room Context Logic

CampusOn eliminates fragmented university ERP forms by connecting physical classrooms with automated scheduling and student welfare. Its central innovation combines official timetables with real-time sensor telemetry to classify rooms into 4 operational states:

Operational State Sensor / Timetable Condition System Meaning
State 1: Class in Session – Unavailable Scheduled Lecture Active + Motion Detected Official lecture in progress. Room unavailable for open student booking.
State 2: Occupied – Open Use No Scheduled Class + Motion Detected Room is being used by students for study or project work.
State 3: Available No Scheduled Class + No Motion (PIR Quiet, Dist > 200cm) Classroom is completely free. Students can request smart access.
State 4: Status Unknown ESP32 Edge Node Offline / Stale Readings Sensor communication interrupted. Failsafe locks room; do not assume empty.

A. Student Dashboard (Shubhi Mathur — BTEC25O1060)

  • Academic Timetable: Real-time daily/weekly view with period badges and room allocations.
  • Digital Student ID: Generates a rotating cryptographic QR code with a 30-second countdown bar. If screenshotted, the token expires automatically to prevent proxy attendance.
  • AI Course Notes (RAG): Queries uploaded course materials with source citations (e.g. ADC2 Wi-Fi pin conflicts).
  • Indoor Campus Map: Interactive 2D floor plan of MITS Block B (Floor 2) with real-time availability colors and turn-by-turn waypoint routing.
  • Student Welfare: Routes requests for scholarships, sports, and counseling. Personal mental health files are tagged as Strictly Confidential.

B. Faculty Dashboard (Dr. Murli Manohar — Centre for IoT)

  • Teaching Schedule: Weekly assigned lectures adhering to the mandatory university policy of >= 3 free daily hours.
  • Timetable Preferences: Faculty submit preferred slots and lab preferences directly to the Google OR-Tools solver.
  • Course Notes Repository: Upload and publish new syllabus units for automated AI vectorization.
  • Classroom Cameras: Permission-gated CCTV snapshot viewer into assigned labs (AB-204) with an automated compliance audit log.

C. Administration Dashboard (Control Tower)

  • Master Room Matrix: Real-time table of all monitored rooms with PIR motion, temperature, humidity, and MQ-2 gas ppm.
  • Google OR-Tools Timetable Optimizer: Constraint Satisfaction solver enforcing zero teacher/room collisions, max 2 consecutive periods, and lab room matching.
  • Campus Safety & Sirens: Incident logging with a functional emergency siren / buzzer toggle for evacuation drills.
  • Analytics: Recharts visualizing hourly classroom utilization curves and departmental attendance percentages.

D. Parent Portal (Mr. R. K. Mathur)

  • Verified student attendance records, semester marks, fee receipts, and official circulars.
  • Student Privacy Shield: Personal student counseling conversations and sensitive grievance files are isolated from parental view via database Row-Level Security (RLS).

3. Hardware Edge Node Wiring & Pinout Guide

The classroom edge node uses an ESP32 microcontroller connected to breadboard sensors as defined in the MITS Milestone 3 schematic:

Hardware Sensor / Actuator Component Pins ESP32 Pin Connection Role in System
PIR Motion Sensor (HC-SR501) VCC, GND, OUT 5V, GND, GPIO 27 Detects infrared from human movement
Ultrasonic Sensor (HC-SR04) VCC, GND, TRIG, ECHO 5V, GND, GPIO 12 (Trig), GPIO 14 (Echo via 1k/2k divider) Desk proximity and occupancy distance
MQ-2 Smoke & Gas Sensor VCC, GND, AO, DO 5V, GND, GPIO 34 (ADC1 Channel) Monitors fire, LPG, and volatile gas hazard
DHT22 Temp & Humidity VCC, GND, DATA 3.3V, GND, GPIO 15 Ambient classroom climate measurement
RFID-RC522 Card Reader 3.3V, GND, RST, SDA, SCK, MISO, MOSI 3.3V ONLY, GND, GPIO 4, 5, 18, 19, 23 Student identity badge & digital attendance
Status LEDs (Green, Yellow, Red) Anode (+), Cathode (-) GPIO 21, 13, 2 (via 220Ω) to GND Visual state (Green=Free, Yellow=In Use, Red=Alert)
Active Piezo Buzzer Positive (+), Negative (-) GPIO 26 to GND Audio alarm for hazard and RFID tap chirp
⚠️ CRITICAL VOLTAGE NOTICE FOR ASSEMBLY:
1. Never connect RFID-RC522 to 5V! It is a 3.3V logic device. Connecting to 5V burns the chip.
2. Voltage Divider on Echo: HC-SR04 outputs 5V. Use 1kΩ and 2kΩ resistors to safely drop it to 3.33V on GPIO 14.

4. Top 10 Viva Questions & Model Answers

Q1: What makes CampusOn an Operating System rather than an ERP?

Answer: Standard college ERPs are passive web forms. CampusOn is an active operating system that connects edge IoT hardware (sensors, smart locks, cameras) with academic management (OR-Tools scheduling, dynamic QR attendance, AI RAG tutors) to make campus operations context-aware and automated.

Q2: What mathematical algorithm generates the timetable?

Answer: We use Google OR-Tools CP-SAT (Constraint Programming - Satisfiability). Scheduling is modeled as an exact mathematical constraint satisfaction problem where hard constraints (no room or faculty clashes, lab allocation) and soft constraints (faculty preferences, minimizing gaps) are optimized simultaneously.

Q3: Why is the QR code dynamic with a 30-second expiry?

Answer: Static QR codes can be screenshotted and shared on WhatsApp to mark fake proxy attendance. CampusOn's QR token regenerates every 30 seconds with a cryptographic hash verified by the backend. Once expired, a screenshot cannot be reused.

Q4: How does CampusOn classify room occupancy into 4 states?

Answer: By fusing timetable data with real-time sensor telemetry: 1. Class in Session (timetable lecture active), 2. Occupied – Open Use (no lecture, but PIR/ultrasonic detect occupants), 3. Available (no lecture, sensors confirm empty), 4. Status Unknown (node offline).

Q5: What is RAG in the AI Course Notes system?

Answer: RAG stands for Retrieval-Augmented Generation. Faculty notes are indexed into text chunks. When a student asks a technical question, the system retrieves only the relevant course paragraphs, passes them to Gemini AI, and answers with the exact source citation without hallucinating.

Q6: How is student privacy protected regarding counseling?

Answer: The system uses Row-Level Security (RLS) in PostgreSQL. Support tickets tagged as Confidential (mental health, sensitive grievances) are isolated. Parents and general staff cannot query or view them—only designated, qualified counseling officers hold decryption access.

Q7: Why can't ADC2 pins on ESP32 be used for the gas sensor?

Answer: On the ESP32, ADC2 pins (GPIO 0, 2, 4, 12-15, 25-27) share internal hardware with the Wi-Fi radio. When Wi-Fi is active, analog reads on ADC2 fail. Therefore, our circuit connects the MQ-2 analog output to ADC1 (GPIO 34), which operates continuously without Wi-Fi conflicts.

Q8: Why did you use a voltage divider for the HC-SR04 ultrasonic sensor?

Answer: The HC-SR04 operates at 5V, so its Echo output is 5V logic. ESP32 GPIO pins tolerate a maximum of 3.6V. We use a 1kΩ and 2kΩ resistor voltage divider to step the 5V signal down to 3.33V, protecting the microcontroller from overvoltage damage.

Q9: What happens if campus internet goes down?

Answer: The ESP32 edge nodes feature local autonomous failsafes. If Wi-Fi drops, the node continues local LED indication, buzzer alarming, and RFID access logging on internal flash memory, syncing back to the cloud as soon as connectivity resumes.

Q10: How was this project validated?

Answer: Validated across 4 milestones at the Centre for Internet of Things, MITS Gwalior, including architectural design (Milestones 1 & 2), circuit schematic design (Milestone 3), and physical cardboard classroom prototype testing with live sensor telemetry (Milestone 4).
